## 3. Security Analytics and Event Investigation

Security analysts often work with large volumes of logs and event data from endpoints, servers, network devices, applications, and other sources.

The challenge is not simply collecting information. It is identifying the portions that matter, understanding the context in which they occurred, and determining whether the evidence suggests routine behavior, a configuration problem, or a potential security incident.

Splunk provides search and analytics capabilities that help security professionals investigate data and develop visibility into system activity.

Through this certification pathway, I am working toward stronger familiarity with the analytical process behind:

- Searching security event data.
- Identifying relevant fields and relationships.
- Narrowing an investigation to a useful time range or set of systems.
- Looking for patterns that may indicate suspicious behavior.
- Correlating related observations.
- Distinguishing an investigative lead from a confirmed incident.
- Documenting the evidence supporting a conclusion.

These skills are relevant to security operations center (SOC) work, incident investigation, and defensive security engineering.

## 4. Threat Hunting and Detection

Threat hunting involves proactively investigating available data to identify activity that may not have been detected by existing automated controls.

It requires a combination of technical knowledge, analytical reasoning, and the ability to develop and test hypotheses.

Rather than assuming that every alert represents an attack, analysts must examine the available evidence and determine what conclusions are justified.

The areas I am working to understand include:

- Recognizing patterns that may indicate malicious activity.
- Investigating suspicious events using supporting evidence.
- Understanding how detection logic influences the alerts analysts receive.
- Evaluating the limitations of existing monitoring.
- Improving investigative queries and detection approaches.
- Communicating findings and identifying opportunities for improvement.

This provides a useful counterpart to offensive security study. Understanding how defensive systems identify activity can help me better appreciate detection opportunities, investigative evidence, and the security controls that protect monitored environments.

## 5. Risk-Based Alerting and Prioritization

Security teams can receive more alerts than they can investigate simultaneously. Effective prioritization is therefore essential.

Risk-based alerting aims to use contextual information and accumulated evidence to help identify activity that deserves greater attention.

The broader lesson is that an alert's importance should not be determined by its existence alone. Analysts must consider the context, the affected systems, the relationship between events, and the potential consequences.

This is relevant to professional security work because it helps distinguish routine noise from activity that may represent a meaningful threat.

I am working toward developing a more structured understanding of how security analytics can support this process and help analysts direct attention toward the most important risks.
